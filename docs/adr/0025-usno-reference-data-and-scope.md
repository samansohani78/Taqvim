# ADR-0025: USNO data is used in full as reference data, and the scope grows to the calendars it covers

- **Status:** Accepted
- **Date:** 2026-09-15
- **Plan reference:** docs/PLAN.md T-103 (Islamic tabular), T-403 (seasons, phases, eclipses; "equinox/solstice
  instants 2020–2040 vs published (±5 min)"), clean-room rules (primary sources, a citation on every record),
  DATA_TODO DT-012 and DT-016, ADR-0003 (permissive dependencies only)

## Context

The US Naval Observatory's Astronomical Applications API (https://aa.usno.navy.mil/data/api.html) is unreachable from
the development network. The Hong Kong Observatory publishes similar data, but its terms forbid commercial use of its
data compilations without written permission, so it cannot be used (DT-012, DT-016).

On 2026-09-15 the owner downloaded the USNO API responses (API version 4.0.1) themselves into
`docs/sources/usno/usno-data/` (191 MB, 36 537 files) and asked that the data be used in full: "add all of data dont
miss all data from firest until end … use comlete source". The download holds seven data sets, each complete (one API
response per year, no missing years):

| Data set | Years | Records |
|---|---|---|
| Earth's seasons and apsides | 1700–2100 | 2 405 |
| Moon phases | 1700–2100 | 19 839 |
| Solar eclipses | 1800–2050 | 582 |
| Islamic observances (tabular) | 622–9999 | 28 996 |
| Jewish observances | 360–9999 | 57 839 |
| Christian movable observances | 1583–9999 | 67 336 |
| US daylight saving time | 1967–9999 | 16 066 |

USNO data is a work of the US Government and is in the public domain (17 U.S.C. §105).

The plan has no Hebrew calendar, no Easter computation and no US daylight-saving check, so using the last three data
sets is a scope decision; the owner made it.

## Decision

- **Archive.** For each data set, the combined file of raw per-year API responses (`<data set>-raw.json`, a byte copy
  of the owner's download) is committed under `docs/sources/usno/`, with SHA-256 checksums in
  `docs/sources/usno/SHA256SUMS`. The rest of the download (per-year files, flattened copies) stays out of git.
- **Goldens.** Every record of every data set is used; no year is sampled out. Golden CSVs under
  `src/test/resources/golden/usno/` in the owning module are generated by scripts from the archived files, never by
  hand, and cite the archive file.
- **Tolerances.** The plan's ±5 minutes applies to seasons in 2020–2040. For other years and for Moon phases, the
  tolerances are set from the measured deviations and documented in the tests. They reflect minute rounding and
  differences between the ΔT models of USNO and the astronomy library. Goldens are never edited to make a test pass.
- **Scope added** (core modules only; no app UI or event sources until a later decision):
  - T-108: Hebrew calendar arithmetic and the six USNO Jewish observances;
  - T-109: Gregorian Easter (computus) and the eight USNO Christian movable observances;
  - T-110: US daylight-saving transitions of the time-zone path the app uses, checked for 1967–9999.
- USNO dates before 1582-10-15 are in the Julian calendar and are converted before comparison.

## Consequences

- About 16.5 MB of JSON is added to the repository (it compresses well in git objects).
- Tests cover up to 8 000 years per data set. Each golden test must add less than about a minute to its module's test
  run.
- The Hebrew calendar and the Christian observances exist in core but are not shown to users yet. Adding them to the
  calendar picker, day details or event sources needs strings in 24 languages and a new decision.
- Disagreements between the app and USNO are reported and investigated, not hidden: a genuine convention difference is
  documented for each affected record in the test.
- HKO data stays unused; DT-016 (Chinese lunar new-year dates) remains open, because USNO has no such data set.
